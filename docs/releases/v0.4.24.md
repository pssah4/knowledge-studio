# Knowledge Studio v0.4.24

This release improves maintenance on slow filesystems, query coverage, editor
reliability, and the adoption and sharing of existing Markdown collections.

## Changes

- **Bounded maintenance and queries.** Source monitoring and synchronization on
  Node run in resumable steps with checked progress. Slow or blocked reads return
  structured errors or incomplete results. Queries and HTML answer exports use
  the same process protection; a read timeout cannot become a successful empty
  answer. Both skills explain how to resume and when to report an unresolved file.
- **More balanced retrieval.** Searches distribute their starting points across
  connected wikis and disclose omitted scope. Shared German word-form and spelling
  matching improves searches in Markdown and retained source evidence.
- **Reliable editing.** Saving preserves text entered while a save is pending,
  the cursor, and the active tab. The toolbar supports guided directed
  relationships, paired footnotes, callouts, highlighting, and offline formulas.
  Previews avoid reading the full collection when graph resolution is unnecessary.
- **Controlled collection adoption.** Read-only assessment reports existing fields,
  values, ambiguities, and unreadable files. Vocabulary mapping and staged upgrades
  provide explicit decisions, previews, and selective undo. MkDocs adoption retains
  navigation groups and ordering and reports later drift.
- **Traceable sharing and participation.** Confirmed transfers between wikis retain
  document identity, referenced assets, and evidence, with content checks before
  transfer. Registered participation fields support filtered overviews. Approved
  ingestion groups track subsequent curation and support selective take-back.
- **Stronger storage and startup behavior.** Vault Operator supports segmented
  transactions for large editor updates and persistent empty folders. Node can
  recover an abandoned writer lock when its former owner is verifiably gone.
  Skill startup carries the essential invocation contract without requiring extra
  reference-file reads; editor handoffs use the verified project entry point.
- **Cleaner distribution.** Successful builds remove recognized obsolete package
  paths, reducing confusion with older archives. Browser regression checks and
  reproducible package checks cover the updated workflows.

## Install or update

Install **both matching v0.4.24 skills** for your platform:

- Claude Code: `claude-code-maintain-llm-wiki.skill` and `claude-code-query-llm-wiki.skill`.
- Claude Cowork: `claude-cowork-maintain-llm-wiki.skill` and `claude-cowork-query-llm-wiki.skill`.
- Codex: extract the two `codex-*.skill` archives into your skills directory.
- ChatGPT: use the two `chatgpt-*.skill` assets in a workspace that supports skills and Node execution.
- Vault Operator: import both `vault-operator-*.skill` assets through its skill manager.

The `llm-wiki-0.4.24.zip` archive provides the combined Claude Code plugin.
Every archive has a SHA-256 checksum; the release manifest lists the platform matrix.

Existing skill names and wiki formats remain compatible. Run maintenance to check
and update the existing project's editor, then reload its browser tab. Installing
new skills alone does not replace an already running editor page.

See the [installation guide](../../README.md#skills-installieren) for host requirements.
