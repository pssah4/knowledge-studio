# Knowledge Studio 0.4.26

Contribute selected documents from a personal or team wiki to other wikis without
sharing the rest of the home folder. Review the exact content, discussion,
attachments and destination before sending; use a folder preview to approve several
files together. Each replica keeps the document's identity and shows who maintains
it and its other approved targets.

New content requires another explicit approval. This includes later journal
messages, attachments and names added to replica notices. Automatic folder marking
can suggest new contributions, but cannot approve their bytes. Target changes
retain their authors and need home acceptance before they continue to another target.

- Contribution, full synchronization and read-only participation connections can
  use the same workspace. Status remains specific to every connection.
- Replicas are protected from normal editing, including when their visible notice
  is missing. Versions and changes supports proposals and local discussions.
- Reviewed lifecycle actions retire, hand over or fork contributions, manage an
  announced takeover, and record intentional bundle identity changes. Interrupted
  actions resume against the reviewed files.
- Delayed journal files and receipts cannot authorize private pause drafts. A file
  from an older contribution phase waits for the corresponding current delivery
  instead of rolling back the home copy.
- Unguarded edits in shared folders are recorded for a decision. SVG and Excalidraw
  attachments receive content clearance, and moved pages use neutral redirects
  without exposing unrelated private paths.
- Source monitoring checks the selected connections, returns compact archive
  decisions and resumes within host time limits. Maintenance reports incomplete
  work across the requested connections; portable documentation paths no longer
  trigger a false content-clearance block.

Contributions require confirmed reader circles and a successful hidden-folder
transport check between two devices. Folder permissions remain with the storage
provider. Previous recipients and cloud version history cannot be recalled.
Automated device tests simulate independent delivery of files and receipts; actual
cloud-folder behavior must still pass the two-device probe on the user's platform.

Install both skills for the same platform and version, then refresh the project
editor. The release contains the five public platform pairs and the combined plugin.
